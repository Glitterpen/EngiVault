# Verify a new organisation workspace

New workspace applications are reviewed by EngiOne. A verified work mailbox proves the applicant can receive mail there; it does not prove that the applicant belongs to the organisation or can open a workspace on its behalf. A declaration alone is not sufficient to activate a workspace.

## Applicant and reviewer steps

1. The applicant verifies their work email through the normal signup flow, then submits their full name, legal organisation name, requested workspace address and official domain in Organisation setup. No workspace or access is granted while the request is pending. Existing Organisation Administrators can request an additional workspace from **Your organisations**.
2. Open **Organisation verification** in the Founder workspace with MFA. Verify the legal entity and its official domain. Use an independently sourced official contact, such as the company's published switchboard or staff directory, to reach someone authorised to confirm the application. Do not rely only on an address or number supplied by the applicant. If the work-email domain differs from the organisation's main domain, verify that the organisation actually issues addresses on it.
3. Ask the representative to confirm both the applicant's current affiliation and explicit authority to open an EngiCite workspace for that entity. The applicant cannot confirm their own request. If either check cannot be confirmed, do not approve. This screen does not contact the company or send an approval email; the applicant can refresh their status in Organisation setup.
4. For approval, record the representative's name and capacity, the contact method, the verified work-email domain and a minimal confirmation reference (for example, an internal case reference). Do not enter passwords, government IDs, staff records or copies of correspondence. The contact evidence stays in the private verification record, not the workspace or applicant status screen. Pending requests expire after 30 days. Applicants can submit again after a decline, expiry or withdrawal.
5. The applicant selects **Create secure workspace** using the approved name and address. Approval lasts 14 days, must match the current verified work email, and can be used once. A request cannot be used with a different email. The workspace creation audit event links to the verification request ID.

The check applies to initial workspace activation; it is not an ongoing certification of a workspace's display name. It does not re-verify existing workspaces, change invitation or sign-in rules, or replace the existing owner-only restoration path. If the approved address becomes unavailable before activation, the applicant can withdraw the unused approval and submit a fresh request with a different address. Do not create a workspace outside this flow to resolve the conflict.

## Release checks

- Confirm work-email confirmation and secure email changes remain enabled, reviewers have enrolled MFA and know how to verify company contacts, and the team checks the queue regularly. Review the retention and handling of these records under EngiOne's privacy process before release.
- Follow the [production release checklist](RELEASE_CHECKLIST.md) on the independently reviewed path. Test migration `202611160130_organisation_owner_verification.sql` and the matching web build together before rolling out. Apply the migration first so the old interface cannot activate a workspace without approval during the transition. If the web release must be rolled back, keep the database gate closed instead of reinstating unchecked creation.
- For the isolated database checks, run `node scripts/test-organisation-owner-verification.mjs <dependency-directory>` with `@electric-sql/pglite` installed in that directory. It uses a disposable local database and no production credentials. Run the web tests for Organisation setup, Founder verification and signup/invitations; verify in a non-production environment that a review and activation succeed and that a pending request cannot activate a workspace or see another request.
